# Flashing and safety notes

JDCloud RE-SS-01 is an eMMC device with A/B-style kernel/rootfs handling in current OpenWrt support. The build itself does not require a separate 64 GB target.

## Before flashing

The production pipeline automatically performs the verified, configuration-preserving standard OpenWrt/ImmortalWrt `sysupgrade` after `AUTO_FLASH_SAFETY_GATE` passes. Manual LuCI clicking is not part of the production path. Raw MTD, U-Boot/bootloader, `dd` raw-partition, raw eMMC/SPI/NAND, and ART/EEPROM/calibration writes remain prohibited.

Back up device-specific data and the partition table before modifying a stock unit. Keep MAC/calibration/device-specific partitions safe. Do not use DiskMan to repartition the system eMMC until you fully understand the partition map.

## First installation from stock firmware

Current OpenWrt support documents an initramfs/TFTP path for stock firmware:

1. Obtain the target initramfs image and serve it as `initramfs.itb` over TFTP.
2. Interrupt U-Boot on supported stock firmware revisions.
3. Load the initramfs image with TFTP and boot it with `bootm`.
4. Once the temporary OpenWrt system is running, install the matching `sysupgrade.bin`.

The exact U-Boot procedure depends on the stock firmware and how you gained console access. Do not flash a generated factory/sysupgrade image into an arbitrary eMMC partition by guessing its number.

## Upgrade from an existing compatible OpenWrt/ImmortalWrt system

Use the JDCloud RE-SS-01 `sysupgrade.bin` generated by the same target. During major source/kernel transitions, do not preserve old configuration blindly; save a backup separately so you can restore settings selectively.
